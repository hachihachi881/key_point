# 2026-10-06 姿勢評価コードの変更内容

## 1. 目的

YOLOv8 Poseを用いた座位姿勢評価について、初期実装では次の問題があった。

- 姿勢指標が一定範囲にある間は100点のままで、姿勢変化がスコアへ連続的に反映されない。
- 閾値を少し超えた瞬間にスコアが大きく低下する。
- 身体全体が前傾していても、一部のスコアが高いまま残り、評価結果を解釈しにくい。
- 頭部前方突出を画面の水平方向だけで計算しており、体幹の傾きを考慮できない。
- 体幹角度に手前側・奥側のどちらの肩と腰を使うべきか比較できない。

これらを改善するため、姿勢指標の計算方法、スコア変換、体幹線の候補保存、実行環境を変更した。

主な実装ファイルは `process_video_yolov8.py` である。

## 2. 変更前の姿勢評価

### 2.1 頭部前方突出

変更前は、耳と肩の水平方向の距離を体幹長で割っていた。

```text
head_forward_ratio = abs(ear_x - shoulder_x) / torso_length
```

ここで、`torso_length` は肩と腰の2点間距離である。

この方法は実装が単純だが、画像の水平方向を基準にしている。そのため、体幹が前傾した場合に「体幹と一緒に頭部が移動した影響」と「体幹に対して頭部だけが前に出た影響」を分離しにくかった。

### 2.2 体幹角度

肩と腰を結ぶ線について、画像の垂直方向からの角度を計算していた。

```text
trunk_angle = angle(shoulder - hip, vertical)
```

角度そのものの定義は現在も同じである。

### 2.3 変更前のスコア

頭部前方突出は以下の規則だった。

```text
0.08以下         100点
0.08から0.15     80点から50点へ線形変化
0.15から0.25     45点から0点へ線形変化
```

体幹角度は以下の規則だった。

```text
10度以下         100点
10度から20度     80点から50点へ線形変化
20度から35度     45点から0点へ線形変化
```

この実装では、体幹角度が10度になるまで100点のままである。また、10度を少し超えた時点で100点付近から80点付近へ急に低下する。同様に、20度の境界にも50点から45点への不連続があった。

したがって、変更前のスコアは一部区間では線形だったが、全体として連続した変化ではなかった。

## 3. 頭部前方突出の計算変更

現在は、耳から体幹線までの垂直距離を用いる。

体幹線は肩と腰を結んだ直線である。耳からこの直線までの最短距離を求め、さらに体幹長で正規化する。

```text
head_forward_ratio
    = distance_perpendicular(ear, shoulder_hip_line)
      / torso_length
```

コードでは `head_forward_ratio_from_torso_line()` がこの処理を担当する。

実際には、肩から腰へのベクトルと、肩から耳へのベクトルの外積を利用して垂直距離を求めている。

```text
torso = shoulder - hip
ear_offset = ear - shoulder
perpendicular_distance = abs(cross(torso, ear_offset)) / length(torso)
head_forward_ratio = perpendicular_distance / length(torso)
```

この変更により、画像の水平方向ではなく、その時点の体幹線を基準として頭部のずれを評価できる。

ただし、身体全体が一本の線に近い状態で前傾した場合、頭部は体幹に対して前方突出していないため、頭部スコアは高くなる。この場合は後述の体幹スコアが低下する。頭部と体幹を別々の姿勢要素として評価する設計である。

## 4. スコア変換の変更

### 4.1 共通の区分線形補間

`piecewise_score()` を追加し、指定した基準点の間を連続した直線で補間するようにした。

この処理により、各境界でスコアが飛ばず、姿勢指標の変化に応じてスコアが連続的に変化する。

### 4.2 現在の頭部スコア

```text
head_forward_ratio = 0.00 -> 100点
head_forward_ratio = 0.04 ->  85点
head_forward_ratio = 0.10 ->  50点
head_forward_ratio = 0.18 ->   0点
```

基準点の間は線形補間する。0.18以上は0点になる。

### 4.3 現在の体幹スコア

```text
trunk_angle =  0度 -> 100点
trunk_angle =  5度 ->  85点
trunk_angle = 15度 ->  50点
trunk_angle = 30度 ->   0点
```

基準点の間は線形補間する。30度以上は0点になる。

### 4.4 変更前後の体幹スコア例

| 体幹角度 | 変更前 | 現在 |
|---:|---:|---:|
| 0度 | 100.0 | 100.0 |
| 5度 | 100.0 | 85.0 |
| 10度 | 100.0 | 67.5 |
| 15度 | 65.0 | 50.0 |
| 20度 | 50.0 | 33.3 |
| 30度 | 15.0 | 0.0 |

変更前は10度まで100点だったが、現在は垂直状態から傾くにつれて徐々に低下する。

### 4.5 変更前後の頭部スコア例

| 頭部前方比率 | 変更前 | 現在 |
|---:|---:|---:|
| 0.00 | 100.0 | 100.0 |
| 0.04 | 100.0 | 85.0 |
| 0.08 | 100.0 | 61.7 |
| 0.10 | 71.4 | 50.0 |
| 0.15 | 50.0 | 18.8 |
| 0.18 | 31.5 | 0.0 |

現在の設定は変更前より早い段階からスコアが低下する。この基準値は現時点では研究用の仮設定であり、医学的に妥当な閾値として確定したものではない。

## 5. 身体が曲がった場合の評価

現在の表示は、頭部と体幹を独立して評価する。

```text
id 0: head 95 / trunk 40
```

身体全体が前傾し、頭部が体幹線上に保たれている場合は次のようになる。

- 頭部と体幹の相対的なずれが小さいため、`head` は高得点になる。
- 体幹が垂直方向から傾いているため、`trunk` は低得点になる。

したがって、「身体が曲がっているのにすべて高得点になる」という問題は体幹スコアによって改善された。一方で、画面上には頭部スコアと体幹スコアが別々に表示されるため、頭部の数字だけを見ると高得点が残っているように見える。

現在は総合姿勢スコアを計算していない。姿勢全体を1つの数値で示す場合は、今後、最小値、加重平均、または専門家評価に基づく統合方法を検討する必要がある。

## 6. 体幹線に使用するキーポイントの変更

### 6.1 手前側の利用

現在の評価用 `trunk_angle` には、カメラから見て手前側と推定した肩と腰を使用する。

`choose_front_side()` では、左右それぞれについて耳、肩、腰のconfidenceを合計し、値が高い側を手前側として選択する。

```text
left_score  = confidence(left_ear, left_shoulder, left_hip)
right_score = confidence(right_ear, right_shoulder, right_hip)
front_side  = side with higher score
```

ただし、この処理は身体の向きそのものを判定しているわけではない。confidenceが高い側を手前側とみなす近似であり、遮蔽や誤検出によってフレームごとに選択側が変わる可能性がある。

### 6.2 比較用角度の追加

手前側、反対側、左右中点のどれが安定した体幹線になるか比較できるよう、次の値を同時に計算してCSVへ保存する。

| CSV列 | 内容 |
|---|---|
| `trunk_angle` | 現在の姿勢評価に使用する手前側の体幹角度 |
| `trunk_angle_left` | 左肩と左腰を結んだ体幹角度 |
| `trunk_angle_right` | 右肩と右腰を結んだ体幹角度 |
| `trunk_angle_opposite` | 手前側と反対側の体幹角度 |
| `trunk_angle_mid` | 左右肩の中点と左右腰の中点を結んだ体幹角度 |

`compare_trunk_angles()` が各候補を計算する。

現時点では、姿勢スコアには `trunk_angle` のみを使用している。他の角度は比較検証用である。

## 7. 姿勢評価CSVの変更

変更前の主な列は以下だった。

```text
time
side
head_forward_ratio
trunk_angle
head_forward_score
trunk_forward_score
bad_reasons
```

現在は体幹線の比較用として、以下の4列を追加した。

```text
trunk_angle_left
trunk_angle_right
trunk_angle_opposite
trunk_angle_mid
```

これにより、動画を再解析しなくても、保存されたCSVから体幹線の候補を比較できる。

## 8. 描画処理とフォントの修正

人物ラベル、信頼度、検出枠、骨格は、Ultralytics標準の `result.plot()` で描画する。

```python
annotated_frame = result.plot()
```

一時的にOpenCVで人物ラベルを独自描画する処理を試したが、既存動画と異なるフォントになったため削除した。

さらに、既存の `2_yolov8.mp4` と新しく生成した動画でYOLO標準ラベルの字形が異なる原因を調査した。

| 環境 | Ultralytics | OpenCV | 表示 |
|---|---:|---:|---|
| 既存動画の環境 | 8.4.83 | 4.13.0.92 | 細い既存フォント |
| 更新後の環境 | 8.4.166 | 5.0.0.93 | 太く詰まったフォント |

Gitの `origin/main` と現在のコードは、どちらも `result.plot()` を使用していた。また、Ultralytics内の該当するOpenCV描画式もほぼ同一だった。

YOLOの英数字ラベルはOpenCVのHersheyフォントで描画されるため、主な原因はOpenCV 5系への更新と判断した。

既存動画と描画を揃えるため、`house_env` を以下へ固定した。

```text
ultralytics==8.4.83
opencv-python==4.13.0.92
```

固定バージョンは `requirements-house-gpu.txt` に記録した。

## 9. GPU実行環境の変更

当初の `house_env` にはCPU版PyTorch `2.8.0+cpu` が入っており、RTX 3060 Tiが利用されていなかった。

現在は、NVIDIAドライバーとの互換性を考慮してCUDA 12.1版へ変更した。

```text
torch==2.5.1+cu121
torchvision==0.20.1+cu121
```

コードはCUDAが利用可能な場合、自動的にGPU 0を選択する。

```python
device = 0 if torch.cuda.is_available() else "cpu"
```

実行時に以下が表示されればGPU推論である。

```text
Device: cuda:0
```

RTX 3060 Tiを用いたYOLOv8 Poseの実推論を行い、CUDAメモリが使用されることを確認した。

## 11. 現在残っている課題

### 11.1 総合姿勢スコア

頭部と体幹は別々に表示されており、姿勢全体を表す1つのスコアはない。単純平均にすると、一方の悪い姿勢がもう一方の高得点で打ち消される可能性があるため、統合方法の検討が必要である。

### 11.2 手前側判定の安定性

現在はキーポイントconfidenceを使って左右を選択している。フレーム間で左右が切り替わると角度が急変する可能性があるため、身体の向き判定、一定時間の多数決、または前フレームの選択を維持する処理が候補となる。

### 11.3 時系列平滑化

現在は各フレームを独立に評価するため、キーポイントの揺れがそのままスコアの揺れになる。移動平均、中央値フィルタ、One Euro Filterなどを比較する必要がある。

### 11.4 前傾と後傾の区別

現在の体幹角度は垂直方向からの角度の絶対値であり、前傾と後傾を区別していない。身体の向きが安定して判定できれば、符号付き角度へ変更できる。

### 11.5 スコア基準の妥当性

現在の基準点は挙動を確認するための仮設定である。理学療法士による評価、文献値、マーカー計測などと比較し、閾値と重みを調整する必要がある。

### 11.6 骨盤傾斜

標準YOLOv8 Poseの17点にはASISやPSISがないため、医学的な骨盤前傾・後傾を直接計測できない。詳細は `research_logs/2026-09-30.md` にまとめている。

## 12. 今後の進め方

優先順位としては以下が考えられる。

1. 同じ動画について `trunk_angle_left`、`trunk_angle_right`、`trunk_angle_mid` の時系列を比較する。
2. 手前側判定がフレーム間で切り替わっていないか確認する。
3. キーポイントとスコアへ時系列平滑化を適用する。
4. 頭部と体幹を統合する場合の総合スコア定義を検討する。
5. 理学療法士評価またはマーカー計測を正解データとして収集する。
6. 正解データに基づいてスコアの基準点を調整する。

## 13. 報告書用要約

初期実装では、頭部前方突出および体幹傾斜のスコアが一定範囲で100点に固定され、閾値を超えた際に不連続に低下する問題があった。そこで、複数の基準点間を線形補間する区分線形スコア関数を導入し、姿勢指標の変化に対してスコアが連続的に変化するよう改善した。体幹スコアは垂直状態の0度を100点、5度を85点、15度を50点、30度を0点とし、従来100点だった10度の前傾は67.5点となる。

また、頭部前方突出の指標を、耳と肩の水平方向距離から、耳と肩・腰を結ぶ体幹線との垂直距離へ変更した。これにより、画像座標の水平方向ではなく体幹を基準として頭部の相対的な突出を評価できる。身体全体の前傾は体幹スコア、体幹に対する頭部の突出は頭部スコアとして分離して評価する。

体幹線については、confidenceが高い側を手前側として評価に使用するとともに、左右それぞれ、反対側、左右中点による角度もCSVへ保存するようにした。これにより、今後は同じ検出結果から複数の体幹線候補を比較できる。

実行環境については、CPU版PyTorchからCUDA 12.1対応版へ変更し、RTX 3060 TiによるGPU推論を可能にした。さらに、OpenCVのバージョン差によってYOLO標準ラベルの字形が変わる問題を確認したため、既存動画と同じUltralytics 8.4.83およびOpenCV 4.13.0.92へ固定した。
