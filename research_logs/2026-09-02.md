# 2026-09-02 姿勢スコアが線形的に変化しない原因と修正案

## 背景

現在の実装では、YOLOv8 Poseで取得したキーポイント座標から座位姿勢の状態を計算し、スコアとして出力している。

主に評価している指標は以下の2つ。

- 頭部前方突出: `head_forward_ratio`
- 体幹傾き: `trunk_angle`

出力結果を確認すると、姿勢スコアが滑らか・線形的に変化していないように見える。

## 現在の計算

### 頭部前方突出

耳と肩のx座標の差を体幹長で正規化している。

```text
head_forward_ratio = abs(ear_x - shoulder_x) / torso_length
```

### 体幹傾き

肩と腰を結ぶベクトルが、垂直方向からどれだけ傾いているかを角度として計算している。

```text
trunk_angle = angle(shoulder - hip, vertical)
```

## 原因

### 1. スコア関数に不連続なジャンプがある

現在の頭部前方突出スコアは、以下のような区分になっている。

```python
if value <= 0.08:
    return 100.0
if value <= 0.15:
    return interpolate_score(value, 0.08, 0.15, 80.0, 50.0)
return interpolate_score(value, 0.15, 0.25, 45.0, 0.0)
```

この設計では、`value = 0.08` までは100点だが、`value` が少しでも0.08を超えると、ほぼ80点まで落ちる。

同様に、`value = 0.15` を超えるところでも、50点付近から45点付近へ小さな段差が発生する。

体幹スコアも同じ構造になっている。

```python
if value <= 10.0:
    return 100.0
if value <= 20.0:
    return interpolate_score(value, 10.0, 20.0, 80.0, 50.0)
return interpolate_score(value, 20.0, 35.0, 45.0, 0.0)
```

そのため、現在のスコアは完全な線形関数ではなく、しきい値の境界で点数が急に変化する。

### 2. 特徴量そのものも線形ではない

スコアの入力になっている特徴量も、単純な線形変化にはならない。

特に `trunk_angle` は角度計算に `acos` を使うため、キーポイント座標が少し変化したときに角度が比例して変化するとは限らない。

また、`head_forward_ratio` も `torso_length` で割っているため、肩・腰の検出位置が揺れると、耳・肩の差が同じでも値が変わる。

### 3. YOLOv8 Poseの検出揺れがある

YOLOv8 Poseのキーポイントは、動画内で完全に安定して検出されるわけではない。

以下の要因でフレームごとに値が揺れる。

- 服や机による関節の隠れ
- カメラ角度
- 低confidenceのキーポイント
- 肩・腰・耳の検出位置の微小なぶれ
- 複数人物がいる場合の検出順の変化

現在はフレーム単位でスコアを計算しているため、この検出揺れがそのままスコアの揺れとして出る。

### 4. 前後方向を厳密には区別できていない

現在の頭部前方突出は以下のように絶対値を使っている。

```text
abs(ear_x - shoulder_x)
```

このため、頭が前に出た場合と後ろにずれた場合を区別していない。

横向きカメラで人物の向きが固定されていればある程度使えるが、カメラ位置や体の向きが変わると、姿勢の意味づけが不安定になる。

## 現時点での結論

現在の計算は、研究初期のルールベース指標としては妥当な出発点である。

ただし、現段階では「正しい姿勢スコア」として確定できるものではなく、以下の課題が残っている。

- スコア関数に不連続な段差がある
- フレーム単位の検出揺れに弱い
- カメラ方向への依存が大きい
- 手動ラベルとの比較検証がまだない
- 頭部前方突出と体幹傾き以外の姿勢要素が未実装

研究上は、現在の方法を「YOLOv8 Poseの2Dキーポイントを用いた簡易的なルールベース姿勢評価」と位置づけるのが適切。

## 修正案

### 1. スコア関数を連続な区分線形関数にする

しきい値を超えた瞬間に点数が大きく落ちないように、区間の端点を連続させる。

頭部前方突出の例。

```text
0.00 - 0.08 : 100 -> 85
0.08 - 0.15 : 85 -> 50
0.15 - 0.25 : 50 -> 0
0.25以上    : 0
```

体幹傾きの例。

```text
0 - 10度   : 100 -> 85
10 - 20度  : 85 -> 50
20 - 35度  : 50 -> 0
35度以上   : 0
```

これにより、スコアの不自然なジャンプを減らせる。

### 2. 移動平均または移動中央値で平滑化する

1フレームごとのスコアは検出揺れの影響を受けやすい。

そのため、以下のような時系列平滑化を入れる。

```text
1秒程度の移動中央値
3秒程度の移動平均
```

外れ値に強くしたい場合は、まず移動中央値を使うのがよい。

### 3. 生の特徴量とスコアを分けて確認する

まずは、以下をグラフ化して確認する。

- `head_forward_ratio`
- `trunk_angle`
- `head_forward_score`
- `trunk_forward_score`

生の特徴量が揺れているのか、スコア関数によって不自然な変化が生じているのかを分けて見る必要がある。

### 4. 頭部前方突出の符号を扱う

カメラ方向と人物の向きを明示できる場合は、絶対値だけではなく符号付きのずれを使う。

```text
signed_head_offset = (ear_x - shoulder_x) / torso_length
```

ただし、右向き・左向きで「前」の向きが逆になるため、カメラ条件を決めてから導入する。

### 5. 手動ラベルとの比較で妥当性を確認する

研究としては、計算式を修正するだけでは不十分。

実際の動画に対して、人が見た姿勢ラベルを付け、スコアと比較する必要がある。

例。

```text
good
caution
bad
head_forward
trunk_forward
```

このラベルと自動スコアの一致度を見ることで、しきい値やスコア関数の妥当性を検証できる。

## 次にやること

1. 現在の姿勢CSVを使って、特徴量とスコアの時系列グラフを作る
2. スコア関数の段差がどこで起きているか確認する
3. `score_head_forward()` と `score_trunk_angle()` を連続な区分線形関数に修正する
4. 移動中央値または移動平均を導入する
5. 数本の動画に手動ラベルを付けて、スコアとの対応を見る

## メモ

現時点の違和感である「スコアが線形的に変化していない」は正しい。

主な原因は、データそのものの揺れだけでなく、現在のスコア設計にしきい値での不連続なジャンプが含まれていること。

そのため、まずはスコア関数を連続化し、その後に時系列平滑化と手動ラベル検証へ進むのがよい。

## 追加検討: 式・計算方法・姿勢判定手法の改善案

### コード確認から見えた現状の課題

現在の `process_video_yolov8.py` では、横向きカメラを前提として、片側の `ear`、`shoulder`、`hip` を使って姿勢を評価している。

主な処理は以下。

```python
head_forward_ratio = abs(ear[0] - shoulder[0]) / torso_length
trunk_angle = angle_from_vertical(shoulder, hip)
```

この方法は簡単で説明しやすいが、姿勢判定としては次の問題がある。

- `abs(ear_x - shoulder_x)` なので、頭が前に出たのか後ろに下がったのか区別できない
- 体幹が傾くと耳と肩のx差も変わるため、頭部だけの前方突出として誤検出しやすい
- `angle_from_vertical()` が符号なし角度なので、前傾と後傾を分けられない
- スコア関数に `100 -> 80`、`50 -> 45` のようなしきい値境界の段差がある
- 評価項目が頭部前方突出と体幹傾きだけで、膝角度、股関節角度、継続時間がまだ入っていない

### 1. 頭部前方突出の式を「体幹線基準」に変更する

現在の式は、画面上のx方向だけを見ている。

```text
head_forward_ratio = abs(ear_x - shoulder_x) / torso_length
```

しかし、日本理学療法士協会系のJ-STAGE論文では、2D矢状面画像上で頭部前方突出度を扱う際に、体幹延長線と耳孔の垂直距離を用いた評価が示されている。

そのため、単なるx差ではなく、肩と腰で作る体幹線を基準にした頭部の前方ずれを見る方がよい。

改善式。

```text
torso = shoulder - hip
u = torso / ||torso||
n = torsoに垂直な前方方向ベクトル
head_forward_ratio = dot(ear - shoulder, n) / ||torso||
```

ここで `n` は、体幹線に対して前方を向く法線ベクトルとする。

前方方向はカメラ条件に依存するため、最初は設定で固定する。

```text
facing = "right" の場合: 画面右方向を前方
facing = "left" の場合 : 画面左方向を前方
```

この方法にすると、体幹が少し傾いた場合でも、頭部が体幹軸からどれだけ前に出ているかを分けて評価しやすい。

### 2. CVA近似指標を追加する

Forward Head Postureの評価では、CVA、つまり耳珠付近と第7頚椎付近を結ぶ線と水平線のなす角度が使われることがある。

YOLOv8 Poseには第7頚椎のキーポイントがないため、厳密なCVAは計算できない。

ただし、肩点を第7頚椎付近の近似点として使い、CVA-like proxyとして追加することはできる。

```text
c7_proxy = shoulder
cva_proxy = angle_between_horizontal(c7_proxy -> ear)
```

判定の初期案。

```text
cva_proxy >= 53度 : 良い
45度 - 53度      : 注意
cva_proxy < 45度 : 悪い
```

ただし、これは肩をC7の代替として使う近似値であり、医学的なCVAそのものではない。
したがって、研究では「CVA近似指標」と明記し、手動ラベルとの比較でしきい値を調整する。

### 3. 体幹角度を符号付きにする

現在の体幹角度は、垂直からどれだけ傾いているかだけを見ている。

```text
trunk_angle = angle(shoulder - hip, vertical)
```

しかし、座位姿勢では前傾と後傾を分ける必要がある。

厚生労働省の腰痛予防や情報機器作業の資料では、椅子に深く腰掛けること、背もたれで体を支えること、極端な前傾姿勢を避けることが示されている。
一方で、軽い後傾や背もたれへの支持は必ずしも悪い姿勢とは限らない。

改善式。

```text
trunk_signed_angle = atan2(torso_x * facing_sign, -torso_y)
```

ここで、前傾がプラス、後傾がマイナスになるように `facing_sign` を設定する。

判定の初期案。

```text
-10度 - +10度 : 良い
+10度 - +20度 : 前傾注意
+20度以上     : 前傾悪い
-10度 - -20度 : 後傾注意
-20度未満     : 後傾強い
```

このようにすれば、前かがみと背もたれに寄りかかりすぎている状態を別々に扱える。

### 4. 膝角度と股関節角度を追加する

医師・医療系の記事では、理想的な座り姿勢として、骨盤が立っていること、背筋が垂直に近いこと、膝角度が90度程度であること、足が床につくことなどが説明されている。

YOLOv8 Poseだけでは骨盤の向きや足裏接地を直接判定できない。
その代わり、膝角度と股関節角度を近似指標として使う。

膝角度。

```text
knee_angle = angle(hip, knee, ankle)
```

判定案。

```text
80度 - 105度                 : 良い
70度 - 80度 / 105度 - 120度 : 注意
70度未満 / 120度超          : 悪い
```

股関節角度。

```text
hip_angle = angle(shoulder, hip, knee)
```

判定案。

```text
90度 - 115度                 : 良い
80度 - 90度 / 115度 - 130度 : 注意
80度未満 / 130度超          : 悪い
```

これにより、頭部と体幹だけでなく、座り方全体を評価できる。

### 5. スコア関数を連続な区分線形関数にする

現在のスコア関数は、しきい値を少し超えた瞬間に点数が大きく落ちる。

この段差をなくすため、複数の制御点を使った連続な区分線形関数に変更する。

頭部前方突出の例。

```text
0.00 -> 100
0.08 -> 85
0.15 -> 50
0.25 -> 0
```

体幹角度の例。

```text
0度  -> 100
10度 -> 85
20度 -> 50
35度 -> 0
```

実装イメージ。

```python
def piecewise_score(value, points):
    if value is None:
        return None
    if value <= points[0][0]:
        return points[0][1]
    for (x0, y0), (x1, y1) in zip(points, points[1:]):
        if value <= x1:
            return interpolate_score(value, x0, x1, y0, y1)
    return points[-1][1]
```

### 6. 1フレーム判定ではなく時系列判定にする

1フレームごとの姿勢スコアは、YOLOv8 Poseの検出揺れの影響を強く受ける。

そのため、以下のような時系列処理を入れる。

```text
生キーポイント
-> confidenceで低信頼点を欠損扱い
-> 座標を1秒移動中央値で平滑化
-> 姿勢特徴量を計算
-> 特徴量またはスコアを3秒移動平均で平滑化
-> 5秒以上継続した悪姿勢を警告判定にする
```

30fpsの場合。

```text
1秒: 30フレーム
3秒: 90フレーム
5秒: 150フレーム
```

この方法により、瞬間的な検出ミスや一時的な動作を悪姿勢として判定しにくくなる。

### 7. 総合判定は重み付きスコアとゲート条件を併用する

現在の表示色は、頭部スコアと体幹スコアの最低点に強く引っ張られる。
注意喚起としては使えるが、総合姿勢スコアとしては極端になる可能性がある。

横向きカメラの場合の総合スコア案。

```text
total_score =
0.30 * head_forward_score
+ 0.25 * trunk_score
+ 0.20 * knee_score
+ 0.15 * hip_score
+ 0.10 * cva_proxy_score
```

ただし、重大な崩れは平均で薄めず、ゲート条件として扱う。

```text
head_forward_score < 50 が5秒以上継続 -> bad
trunk_score < 50 が5秒以上継続       -> bad
必要キーポイントのconfidence不足     -> 判定不能
```

総合スコアは全体傾向の表示、ゲート条件は明確な悪姿勢の検出に使う。

### 8. 研究としてのおすすめ手法

現段階では、以下の順番で進めるのがよい。

1. 現在のルールベースを改善する
2. 体幹線基準の頭部前方突出、CVA近似、符号付き体幹角度、膝角度、股関節角度を追加する
3. 時系列平滑化と5秒継続判定を入れる
4. 数本の動画に手動ラベルを付ける
5. 自動スコアと手動ラベルの一致度を確認する
6. しきい値を調整する
7. 必要に応じて、Random Forest、SVM、LightGBMなどの機械学習分類に進む

研究発表では、以下のように表現するとよい。

```text
2D姿勢推定キーポイントから、体幹線基準の頭部前方突出、CVA近似、体幹前後傾、膝・股関節角度を算出し、時系列平滑化と継続時間条件により座位姿勢を推定する。
```

### 実装優先順位

1. `abs(ear_x - shoulder_x)` を体幹線基準の前方距離に変更する
2. `trunk_angle` を符号付き前傾・後傾角度に変更する
3. スコア関数を連続な区分線形関数に変更する
4. `knee_angle` と `hip_angle` を追加する
5. `total_score` と `posture_label` を追加する
6. 1秒移動中央値、3秒移動平均、5秒継続判定を追加する
7. 手動ラベルCSVを作り、しきい値を検証する
